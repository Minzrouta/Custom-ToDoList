Créer le `Dockerfile` à la racine du projet avec le pattern multi-stage officiel Next.js standalone :

```dockerfile
# Dockerfile
# Stage 1: Dependencies
FROM node:20-alpine AS deps
RUN apk add --no-cache libc6-compat openssl
WORKDIR /app

COPY package.json package-lock.json* ./
RUN npm ci

# Stage 2: Builder
FROM node:20-alpine AS builder
RUN apk add --no-cache openssl
WORKDIR /app

COPY --from=deps /app/node_modules ./node_modules
COPY . .

# Générer le client Prisma
RUN npx prisma generate

# Variables NEXT_PUBLIC_* doivent être disponibles au build
ARG NEXT_PUBLIC_APP_URL=https://tasks.bantou.me
ENV NEXT_PUBLIC_APP_URL=$NEXT_PUBLIC_APP_URL

ENV NEXT_TELEMETRY_DISABLED=1
ENV NODE_ENV=production

RUN npm run build

# Stage 3: Runner
FROM node:20-alpine AS runner
RUN apk add --no-cache openssl
WORKDIR /app

ENV NODE_ENV=production
ENV NEXT_TELEMETRY_DISABLED=1

RUN addgroup --system --gid 1001 nodejs
RUN adduser --system --uid 1001 nextjs

# Copier les fichiers publics et le build standalone
COPY --from=builder /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static

# Copier le schema Prisma pour les migrations runtime
COPY --from=builder /app/prisma ./prisma
COPY --from=builder /app/node_modules/.prisma ./node_modules/.prisma
COPY --from=builder /app/node_modules/@prisma ./node_modules/@prisma

USER nextjs

EXPOSE 3000
ENV PORT=3000
ENV HOSTNAME="0.0.0.0"

CMD ["node", "server.js"]
```

Notes importantes :
- `openssl` est requis par Prisma sur Alpine
- Le stage runner copie les fichiers Prisma générés (`.prisma` et `@prisma`) car le client est lié à l'OS de build
- `NEXT_PUBLIC_APP_URL` est déclarée comme ARG (baked au build) et ENV (disponible au runtime)
- Le serveur Next.js standalone écoute sur `server.js` à la racine du standalone

Créer `docker-compose.yml` à la racine :

```yaml
# docker-compose.yml
# Compatible Coolify 4.0 — contraintes appliquées :
# 1. Pas de env_file (le fichier .env n'existe pas sur le serveur)
# 2. NEXT_PUBLIC_* passées en build.args ET en environment (baked au build + disponibles au runtime)
# 3. Label traefik.docker.network=coolify pour éviter le bug de routing réseau Traefik
# 4. Réseau coolify déclaré comme external (existe déjà sur le VPS)

services:
  web:
    build:
      context: .
      dockerfile: Dockerfile
      args:
        # NEXT_PUBLIC_* sont baked au build — doivent être ici
        NEXT_PUBLIC_APP_URL: ${NEXT_PUBLIC_APP_URL:-https://tasks.bantou.me}
    environment:
      # Variables runtime (non baked)
      NODE_ENV: production
      DATABASE_URL: ${DATABASE_URL}
      NEXTAUTH_URL: ${NEXTAUTH_URL:-https://tasks.bantou.me}
      NEXTAUTH_SECRET: ${NEXTAUTH_SECRET}
      # NEXT_PUBLIC_* répétées en environment pour accès runtime si besoin
      NEXT_PUBLIC_APP_URL: ${NEXT_PUBLIC_APP_URL:-https://tasks.bantou.me}
    depends_on:
      database:
        condition: service_healthy
    networks:
      - coolify
    labels:
      # Traefik routing
      - "traefik.enable=true"
      - "traefik.http.routers.custom-todolist.rule=Host(`tasks.bantou.me`)"
      - "traefik.http.routers.custom-todolist.entrypoints=https"
      - "traefik.http.routers.custom-todolist.tls=true"
      - "traefik.http.routers.custom-todolist.tls.certresolver=letsencrypt"
      - "traefik.http.services.custom-todolist.loadbalancer.server.port=3000"
      # CRITIQUE : indique à Traefik quel réseau Docker utiliser
      - "traefik.docker.network=coolify"
    restart: unless-stopped

  database:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: ${POSTGRES_DB:-custom_todolist}
      POSTGRES_USER: ${POSTGRES_USER:-postgres}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    networks:
      - coolify
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER:-postgres} -d ${POSTGRES_DB:-custom_todolist}"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 10s
    restart: unless-stopped

volumes:
  postgres_data:
    driver: local

networks:
  coolify:
    external: true
```

Mettre à jour `.gitignore` pour s'assurer que `.env` et les fichiers sensibles sont exclus. Lire le `.gitignore` existant d'abord et ajouter si manquant :

Note sur les variables Coolify : DATABASE_URL doit être construite depuis les variables composantes :
```
DATABASE_URL=postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@database:5432/${POSTGRES_DB}
```
Dans Coolify, injecter `DATABASE_URL` directement avec cette valeur (en remplaçant les vars par leurs valeurs réelles), pas via interpolation Docker.

Note sur `depends_on condition: service_healthy` : le service `web` ne démarre qu'une fois PostgreSQL healthy (pg_isready passe). Cela évite les erreurs de connexion DB au démarrage.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet → Traefik → web service | Tout trafic entrant passe par Traefik ; le service web n'est pas exposé directement |
| web service → database | Connexion interne Docker uniquement, postgres non exposé sur le host |
| Coolify → docker-compose.yml | Coolify injecte les secrets — ne jamais les committer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-07 | Information Disclosure | POSTGRES_PASSWORD en environment | mitigate | Injecté par Coolify uniquement — jamais dans le fichier docker-compose.yml committé (valeur via ${POSTGRES_PASSWORD} seulement) |
| T-01-08 | Information Disclosure | NEXTAUTH_SECRET en environment | mitigate | Même pattern — valeur injectée par Coolify, jamais hardcodée |
| T-01-09 | Elevation of Privilege | Container web tournant en root | mitigate | Dockerfile crée un user `nextjs` non-root (uid 1001) et `USER nextjs` avant CMD |
| T-01-10 | Denial of Service | Port PostgreSQL exposé publiquement | mitigate | Aucun `ports:` pour le service database — accessible uniquement via réseau Docker interne `coolify` |
| T-01-11 | Spoofing | Traefik routing sans label network | mitigate | Label `traefik.docker.network=coolify` force Traefik à utiliser le bon réseau, évitant routing vers mauvaise interface |
</threat_model>
