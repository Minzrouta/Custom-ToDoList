Structure PUT (calquée sur discord/route.ts PUT) :
1. `const session = await auth();` → 401 si pas de session.
2. `try { const { id } = await params;` puis `const member = await requireMembership(id, session.user.id);` → 403 si pas membre OU si `member.role !== "OWNER"`.
3. `const body = await request.json();` → destructurer `{ gitlabProjectId, gitlabBaseUrl, regenerateSecret }` typés `string | null | undefined` et `boolean | undefined`.
4. Validation `gitlabBaseUrl` : si fourni non vide, doit matcher `/^https?:\/\/.+/` ; sinon `Response.json({ error: "Base URL invalide (http(s)://... attendu)" }, { status: 400 })`.
5. Lire l'état courant : `const current = await prisma.workspace.findUnique({ where: { id }, select: { gitlabWebhookSecret: true } });`
6. Calculer `newSecret` : `regenerateSecret || !current?.gitlabWebhookSecret ? randomBytes(32).toString("hex") : current.gitlabWebhookSecret`.
7. `prisma.workspace.update({ where: { id }, data: { gitlabProjectId: ..., gitlabBaseUrl: ..., gitlabWebhookSecret: newSecret }, select: { id, gitlabProjectId, gitlabBaseUrl, gitlabWebhookSecret } });` — convertir `""` en `null` pour les champs string (pattern identique à discord/route.ts).
8. `return Response.json({ data: workspace });`
9. catch → `console.error("[gitlab-config:PUT]", error);` + `Response.json({ error: "Erreur interne" }, { status: 500 });`.

Structure DELETE (calquée sur discord/route.ts DELETE) :
- Auth + requireMembership + role check identiques.
- `prisma.workspace.update({ where: { id }, data: { gitlabProjectId: null, gitlabBaseUrl: null, gitlabWebhookSecret: null } });`
- `return Response.json({ success: true });`
- catch → `console.error("[gitlab-config:DELETE]", error);`.

Pas de POST, pas de GET (le secret est déjà chargé par la page settings via Prisma server-side ; pas besoin d'endpoint GET).
